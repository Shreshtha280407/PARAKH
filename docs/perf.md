# Performance report (P10.3)

Status: **real backend measurements collected and regenerable; dashboard-browser,
network-degraded and Android/device-tier timing NOT measured in this pass** -- see
the explicit gap list below. Do not read any section of this report as covering
a category it does not actually cover.

## What this report is, and is not

- Backend numbers below are real HTTP round-trip measurements against a live,
  disposable FastAPI + PostgreSQL stack on this development machine
  (`docker compose -f infra/docker-compose.yml`), produced by
  `tools/perf_report.py`. They are not synthetic, not mocked, and not estimated.
- They measure *this machine's* performance, not a production server's. They are
  useful for regression tracking (did a change make this materially slower?), not
  for capacity planning on unknown target hardware.
- Android on-device assistance timing is **not re-measured here** -- the existing,
  real, dated OnePlus 13R benchmarks already in this repository
  (`docs/evidence/Q2_Q3/oneplus13r-benchmark-final.json`, recorded 2026-10-15/16)
  are the current, honest Android performance evidence and are referenced, not
  reproduced. They remain subject to the limitations already disclosed in
  `docs/gates/Q2_Q3_acceptance.md` and `docs/assistance_modules.md` (flagship-only
  hardware; no entry/mid-tier measurement; Q3 decoder-fix timing documented there).

## 1. Backend (real, this pass)

Source: `docs/evidence/P10/perf-backend-2026-10-16.json`, generated by:

```sh
docker compose -p perf-test -f infra/docker-compose.yml up -d --build
docker compose -p perf-test -f infra/docker-compose.yml exec -T api python -m app.pack_import
docker compose -p perf-test -f infra/docker-compose.yml exec -T \
  -e PROVISION_ASSESSOR_PASSWORD=<test-only> \
  api python -m app.provision_assessor --email perf@test.local --display-name "Perf"
server/.venv/bin/python tools/perf_report.py --base-url http://127.0.0.1:<api-port> \
  --assessor-email perf@test.local --assessor-password <test-only> \
  --repeat 20 --out docs/evidence/P10/perf-backend-2026-10-16.json
docker compose -p perf-test -f infra/docker-compose.yml down -v   # disposable stack, torn down after
```

Commit measured: `6cd169330b4744432b1f27ebf03b71e7b6caf477` plus this branch's
uncommitted P10 changes. Host: this development machine, not representative of any
specific hosted deployment's hardware.

| Scenario | n | median | p95 | min | max | failures |
|---|---:|---:|---:|---:|---:|---:|
| `auth_login` (Argon2 verify + JWT issue) | 20 | 95.2 ms | 111.7 ms | 81.5 ms | 111.7 ms | 0 |
| `queue_retrieval` | 20 | 6.2 ms | 19.5 ms | 4.9 ms | 19.6 ms | 0 |
| `assessment_bootstrap_register_plus_create` (worker self-register + create) | 20 | 33.6 ms | 52.9 ms | 16.1 ms | 53.1 ms | 0 |
| `rubric_retrieval` (71 PCs) | 20 | 15.7 ms | 32.8 ms | 7.9 ms | 33.1 ms | 0 |

Argon2's deliberate work factor dominates `auth_login`'s latency (by design --
this is a password hash, not a lookup); the other three are plain PostgreSQL
reads/writes through SQLAlchemy and are all sub-35ms at the median.

### Not measured by `tools/perf_report.py` in this pass

PC score save, computed-competency-profile generation, reassessment-request
creation, signed-report generation and public verify all require a `submitted`
assessment with real evidence (or at least a passed submit-gate); reproducing
that purely for a timing harness was out of scope for this pass. These same
operations were exercised *functionally* (not timed) for real, end-to-end, by
`apps/dashboard/e2e/p10-workflow.mjs` (see `docs/gates/P10.md`) -- i.e. they are
known to work, just not benchmarked yet. Manifest-signature verification and
chunked-evidence-upload timing are likewise untimed here; their functional
correctness (including interruption/resume) is covered by
`tools/docker_e2e_smoke_p6.py` and the existing P6/P7 test suites, not by this
report. **Status: NOT VERIFIED (timing only -- functionally verified elsewhere).**

## 3. Android

**NOT VERIFIED in this pass; existing historical measurements referenced, not
reproduced.** Real, dated OnePlus 13R (flagship) measurements already exist:

- `docs/evidence/Q2_Q3/oneplus13r-benchmark-final.json`: Q2/Q3 init/inference
  timings (warm inference mean 99.731 ms, p50 91.439 ms, p95 198.441 ms).

original `<=5s/video-minute` entry-phone and `<=60ms/frame` mid-phone targets)
is **NOT VERIFIED** -- no such device has ever been available to this project
(`docs/gates/Q2_Q3_acceptance.md`). This P10 pass did not acquire one either.

A real OnePlus 13R (serial `d34cebae`) was connected during this P10 pass and
used for functional regression (22/22 instrumented tests, real release-build
install/launch -- see `docs/gates/P10.md`), not for new timing measurements.
