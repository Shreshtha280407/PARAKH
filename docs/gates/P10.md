## P10.3 — performance

### Second pass (this update): error-handling fixes + three remaining gaps closed

The original `tools/perf_report.py` had two real bugs, both found and fixed
this pass, with regression tests:

1. An unreachable server or an unimported pack crashed the whole script
   with a raw traceback, discarding any already-collected results. Fixed:
   every connection-level and HTTP-level failure is now a normal reportable
   outcome; a stage whose prerequisite failed is marked `"skipped"` with a
   reason instead of crashing or silently showing `0/0`.
2. `queue_retrieval` and `rubric_retrieval` never checked the HTTP status at
   all — any error response (even a 500) was timed and reported as a
   successful observation, since nothing inspected the returned status.
   Fixed: every call site now routes through a shared `expect()` helper.

Both fixes are covered by 18 new regression tests
(`tools/tests/test_perf_report.py`, `test_perf_upload.py`,
`test_offline_bundle.py`; mocked HTTP/Docker, no live stack needed, wired
into CI's new `tools-tests` job) and were additionally verified against a
**real** live stack: a genuinely unimported pack, a genuinely stopped API
container, and a real full success path were each exercised by hand and
confirmed to produce the correct JSON shape with exit code 0, no crash.

The three performance measurements the original P10 pass left as NOT
VERIFIED are now measured, for real:

| Gap | Tool | Result |
|---|---|---|
| Upload verification timing | new `tools/perf_upload.py` (real ECDSA-signed manifest + real sequential chunked upload, reusing `docker_e2e_smoke_p6.build_signed_manifest`) | manifest verify ~53ms median; 2 MiB photo upload+verify ~100ms; 8 MiB video upload+verify ~276ms |
| Throttled (256 KiB/s) upload timing | `tools/perf_upload.py` driven through the existing `tools/p8_network_proxy.py` loopback cap against the real `infra/docker-compose.p8-test.yml` stack | 1 MiB upload: 107ms unthrottled vs. 4203ms throttled — within 5% of the 4000ms theoretical floor |
| Dashboard load timing | new `apps/dashboard/e2e/perf-dashboard.mjs` (real Playwright/Chrome wall-clock timing) | login page load ~98ms; full login→queue round trip ~238ms; authenticated queue reload ~77ms; assessment-detail load ~12ms |

Also hardened `tools/offline_bundle.py`'s no-pull contract: added a `verify`
subcommand that loads the tar and starts the stack with both `--no-build`
**and** `--pull never` (closing the narrower gap that `--no-build` alone
only forbids *building*, not fetching the `db` service's directly-referenced
`postgres:16-alpine` image), validates the tar's own `manifest.json` lists
every required image before touching Docker at all, and wraps every Docker
failure as a clean one-line message instead of a raw traceback. Re-verified
for real this pass (images deleted, reloaded from tar, started with
`--no-build --pull never`, confirmed healthy, torn down) using the new
automated `verify` subcommand instead of by-hand terminal commands, and
wired into a new independent CI job (`offline-bundle-verify`) that performs
the same real round-trip on every run.

Full numbers, methodology, and the one remaining honestly-disclosed gap
(Android device-tier timing, referencing existing historical measurements
rather than re-running them) are in `docs/perf.md` — do not read a category
there as measured if it's listed as NOT VERIFIED.

### Manual acceptance checklist (for the team's own real assessment)

1. `cp .env.example .env`, fill in real secrets; `docker compose -f infra/docker-compose.yml up -d --build`.
2. `docker compose ... exec api python -m app.pack_import`.
3. `docker compose ... exec api python -m app.provision_assessor --email <you> --display-name "<name>"`.
4. Open `http://localhost:5173`, log in with that account.
5. Build and install the Android app on a real device (`./gradlew :app:assembleDebug`, point its debug sync field at your laptop's LAN IP) and complete a real worker declaration + capture through to sync.
6. In the dashboard: open the queue, start review, score at least one PC (try leaving a comment blank on a non-`DEMONSTRATED` status to see the validation), load the competency profile.
7. Request a targeted reassessment for one task; confirm only that task shows as reopened.
8. Sign off (your real password), download the PDF, open "Open public verify page" and confirm it loads with **no login** (try it in a private/incognito window).
9. Log out; confirm the queue is no longer reachable.
10. Report anything that looks wrong, confusing, or broken — that's exactly what this checklist is for.
